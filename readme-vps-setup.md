## 1. Initial Access & SSH Hardening

The first line of defense is securing how you access your VPS from the server side.

* **Use SSH Key Authentication Only:** Disable password-based logins completely.
* **Disable Root Login:** Do not allow direct SSH login as `root`.
* **Change the Default SSH Port (Optional):** Moving SSH away from port `22` (e.g., to `2222` or a custom high-range port) reduces automated bot scanning noise.
* **Configure SSH Client Alive Signals:** Prevent dropped connections by setting `ClientAliveInterval`.

### Recommended `/etc/ssh/sshd_config` (Server Side):
```ini
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
KbdInteractiveAuthentication no
Port 2222  # Or your chosen custom port
ClientAliveInterval 300
ClientAliveCountMax 2
```

## 2. Local macOS SSH Configuration (`~/.ssh/config`)

To easily manage and connect to your server from your Mac without typing long IP addresses, ports, or identity files every time, configure your local SSH client config file.

### Where SSH Configs & Keys Are Stored on macOS:
* **Config file path:** `~/.ssh/config`
* **SSH keys path:** `~/.ssh/id_rsa`, `~/.ssh/id_ed25519`, or custom key files (e.g., `~/.ssh/oracle_vps`).

### Setting Up `~/.ssh/config` on macOS:
1. Open Terminal on your Mac and edit/create the SSH config file:
   ```bash
   nano ~/.ssh/config
   ```
2. Add your server profile entry:
   ```ini
   Host my-vps
       HostName 79.72.43.109
       User your-username
       Port 2222
       IdentityFile ~/.ssh/oracle_vps
       ServerAliveInterval 60
       ServerAliveCountMax 3
   ```
3. Set strict file permissions (required by macOS/OpenSSH):
   ```bash
   chmod 600 ~/.ssh/config
   chmod 700 ~/.ssh
   ```
4. Now you can connect instantly by typing:
   ```bash
   ssh my-vps
   ```

## 3. User & Privilege Management

* **Create a Non-Root Sudo User:** Use a dedicated username with administrative privileges via `sudo`.
* **Enforce Strong Password Policies:** Use long, random passwords generated by a password manager for `sudo` verification.
* **Restrict Sudo Privileges:** Configure `/etc/sudoers` carefully if specific automated scripts or services require elevated access.

## 4. Firewall Configuration (Network Layer)

Implement a strict "Default Deny" inbound traffic policy.

### Using UFW (Uncomplicated Firewall):
```bash
# Set default policies
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow SSH on your custom port
sudo ufw allow 2222/tcp

# Allow HTTP and HTTPS (if running web services)
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Enable firewall
sudo ufw enable
```

### OCI Security Lists / Network Security Groups (NSGs):
* Ensure your **Oracle Cloud Console** Security List rules match your OS firewall. Block all inbound ports except the specific custom SSH port and web ports (`80`, `443`).

## 5. Intrusion Prevention & Brute-Force Defense

* **Fail2ban:** Automatically bans IP addresses after multiple failed login attempts.
  * Protects SSH, Nginx/Apache, and custom authentication endpoints.
  * Example Jail Configuration (`/etc/fail2ban/jail.local`):
    ```ini
    [sshd]
    enabled = true
    port = 2222
    filter = sshd
    logpath = /var/log/auth.log
    maxretry = 3
    bantime = 1d
    ```
* **CrowdSec (Modern Alternative/Complement):** A crowd-sourced threat intelligence engine that detects malicious IP behaviors across networks and blocks them automatically.

## 6. System Updates & Patching

* **Keep Packages Up to Date:**
  ```bash
  sudo apt update && sudo apt upgrade -y   # Debian/Ubuntu
  # OR
  sudo dnf update -y                      # Oracle Linux/RHEL
  ```
* **Automate Security Updates:** Install `unattended-upgrades` (Debian/Ubuntu) or `dnf-automatic` (RHEL/Oracle Linux) to automatically apply critical security patches without manual intervention.

## 7. System Hardening & Auditing Tools

* **Lynis:** An open-source security auditing tool. Run `sudo lynis audit system` to get a security score and actionable hardening suggestions for your specific OS.
* **AIDE (Advanced Intrusion Detection Environment):** Monitors file system integrity and alerts you if core system binaries or critical files are tampered with.
* **RKHunter / Chkrootkit:** Scans the system for installed rootkits, backdoors, and hidden exploits.

## 8. Web Application & Container Security

If you run Docker containers, web applications, or API services:

* **Reverse Proxy Hardening (Nginx / Traefik / Caddy):**
  * Use **SSL/TLS Certificates** via Let's Encrypt (`certbot`).
  * Force HTTP to HTTPS redirects.
  * Enable security headers:
    ```nginx
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header X-XSS-Protection "1; mode=block";
    add_header Referrer-Policy "strict-origin-when-cross-origin";
    ```
* **Container Security (Docker):**
  * Avoid running containers as `root` user (`USER node` or `USER 1000` in Dockerfiles).
  * Expose container ports only to `127.0.0.1` locally rather than `0.0.0.0` unless routed through a firewall/proxy.

---

## 9. Backup & Recovery Strategy

* **Off-Site Backups:** Always send encrypted backups off the VPS (e.g., AWS S3, Cloudflare R2, or remote server via `rclone` or `BorgBackup`).
* **Automated Boot Volume Snapshots:** Enable periodic cloud snapshots in the Oracle Console for point-in-time recovery.
